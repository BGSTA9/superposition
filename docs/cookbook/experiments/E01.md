## 1. Claim and pages

**The paper's claim (pp. 10–12).** Two settings: n = 20 features in m = 5 dimensions with
Iᵢ = 0.7ⁱ (p. 11), and n = 80, m = 20 with Iᵢ = 0.9ⁱ (p. 12).

- The *linear model* always learns the top m features, orthogonally, at every sparsity.
- The *ReLU output model* matches it on dense data.
- As sparsity rises, the ReLU model represents more features than it has dimensions
  (*superposition*), first among the less important features, first as *antipodal pairs*,
  then in other geometries.

The figure grid of p. 11 shows WᵀW, the bias, and per-feature norm bars colored by how much
each feature shares its direction (the *superposition score*, Σ_{j≠i}(Ŵᵢ·Wⱼ)²).
([SPEC.md](../../../SPEC.md) §7 E01; [REPRODUCTION.md](../../REPRODUCTION.md) § E01.)
**[Documented]**

### 4b. Doing it by hand

**[Recommended]** for every step below.

1. **Turn each worded criterion into a test before training.** Write down, for each SPEC
   sentence, the exact quantity, the threshold and the setting it is evaluated on. Compare
   with D-105 afterwards.
   - Check: for each rule, build one tiny hand-made W that should pass and one that should
     fail. `test_e01_superposition_order_criterion` in
     `tests/unit/test_experiment_criteria.py` is the model.
   - If you cannot write a failing example, the criterion is too vague. Tighten it now, not
     after the run.
2. **Train both settings as two batched grids.** 7 sparsities × 4 restarts = 28 instances per
   model kind and setting. Give the linear and ReLU grids the same seed, so each ReLU instance
   starts from its linear twin's W (D-103).
   - Command for the repo's answer: `uv run superposition run basic_results --profile quick --device cpu`.
   - Expected: about 8 minutes on a laptop CPU; PASS 12/12.
3. **Count represented features per sparsity on the best restart.** Represented means
   ‖Wᵢ‖ > 0.5.
   - Expected (cited run): 5 → 7 → 9 → 11 → 12 → 12 → 14 for n = 20, and 20 → 27 → 33 → 41
     → 52 → 61 → 67 for n = 80.
   - If your sparsest counts differ by one or two: re-select the best restart on more samples
     before suspecting the model (R1-06).
4. **Compare with the paper's figure at full resolution.** Render pp. 11–12 at 300 dpi and
   count by eye, writing the reading down as approximate.
   - If your count disagrees with a low-resolution reading: re-read at 300 dpi before you write
     a decision (the D-113 → D-114 lesson).
5. **Find where superposition starts.** At the densest sparsity where any feature has score
   > 0.05, list the superposed and the orthogonal represented features.
   - Expected: at 1 − S = 0.3, features 3–6 superposed and 0–2 orthogonal (n = 20).
